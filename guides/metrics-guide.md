# Sprint Metrics Evaluation Guide

スプリント全体の品質とプロセス規律を定量評価するためのガイドラインです。 各指標は **数値（Goal
Achievement / Estimation Accuracy / Quality Integrity / Collaboration Discipline は
1〜5スコア、Velocity はウェイト換算値）** と **ナラティブ（定性説明）** の両方を必ず記録します。
ナラティブなしの数値のみは、数値のゲーム化・目的化を招くため許容しません。

## 評価指標の定義

### 1. Goal Achievement Rate (ゴール達成率)

- **定義**: 計画されたPBIおよびスプリントゴールに対する完了の割合。
- **採点基準**:
  - 1: スプリントゴールが未達で、PBIの半分以上が未完了のまま残った。
  - 3: スプリントゴールは一部達成され、主要なPBIが完了した。
  - 5: すべてのPBIを完遂し、スプリントゴールを完璧に達成した。
- **ナラティブ**: 達成・未達の具体的な内容と、未達要因を記述する。

### 2. Estimation Accuracy (見積もり精度)

- **定義**: PBIの見積時Tシャツサイズ（具体的なポイント換算基準は
  [backlog-guidelines.md の「2.2. PBI の見積り基準 (T-Shirt Size)」](/guides/backlog-guidelines.md)
  を参照）と、完了までに実際に要した労力（セッション数）の乖離度合い。
- **採点基準**:
  - 1: 見積もりに対して実際の労力が極めて重かった、またはほぼ消化できなかった。
  - 3:
    Tシャツサイズと実際の労力に多少のブレ（思ったより大きかった/小さかった等）はあったが、概ね妥当なペースで消化された。
  - 5: 見積もられたTシャツサイズ通りの労力で、事前の予測通りにスムーズにPBIが消化された。
- **ナラティブ**: 乖離が生じたPBIとその原因（要求の曖昧さ、予想外の技術的困難等）を記述する。

### 3. Quality Integrity (品質健全性)

- **定義**:
  スプリントを通じてマージされたコード全体の品質（リリースビルド・CI/CDの健全性、回帰テストの成功、および全体のテストカバレッジ維持）。
- **採点基準**:
  - 1: リファクタリングによる他機能の破損や、ビルドエラーがスプリント中に多発した。
  - 3: 軽微なバグの修正はあったが、最終的にリリース品質およびテスト網羅性が維持された。
  - 5:
    スプリント最終成果物の全自動テストが完全に成功し、手戻りや回帰バグの発生なくクリーンな状態が保たれた。
- **ナラティブ**: 発生した品質問題とその対処、テスト網羅性の維持状況を記述する。

### 4. Collaboration Discipline (協働品質とプロセス規律)

- **定義**: セッションメトリクス（Sprint Board の `harness-metrics-summary` と4指標ナラティブ
  独立フィールドに記録された Intent / Constraint / Context Extraction / Work Size Stability の
  スコア）の健全性と、スプリントを通じた運用規律（セレモニーの確実な遂行、アトミックコミットの
  徹底）の総合評価。
- **採点基準**:
  - 1:
    セッションメトリクスが慢性的に低く（やり直しが多発）、セレモニーのスキップ等でプロセスの規律が乱れた。
  - 3:
    メトリクスに多少の波はあったが、原則としてすべてのスプリント境界ルールと協働プロトコルが守られた。
  - 5:
    すべてのセッションが高いメトリクスを叩き出し、あらゆるセレモニーと一時クリーンアップが完璧に実行された。
- **ナラティブ**: セッションメトリクスの傾向と、プロセス規律の遵守・逸脱状況を記述する。

### 5. Velocity (規模消化力)

- **定義**: 完了したPBIの**実感サイズ（Tシャツサイズ）**をウェイト換算した値の集計による
  独自ベロシティ。ウェイト換算基準は
  [backlog-guidelines.md の「2.2. PBI の見積り基準 (T-Shirt Size)」](/guides/backlog-guidelines.md)
  を参照。
- **算出**: `ΣPBI(実感サイズ × ウェイト換算値)`
- **スコアは不要**: Velocity は1〜5スコアで評価せず、ウェイト換算値（Σ）をそのまま記録する。
  数値を「上げること」を目的化しない（数値のゲーム化・目的化はアンチパターン）。
- **ナラティブ（必須）**: Velocity
  は数値のみでは意味をなさない。**乖離要因・文脈**（見積と実感の差異、予想外の要因、
  計画の変更等）を定性的に必ず記述し、次スプリントの改善に活かす。数値よりもナラティブを
  重視し、次のプランニングの判断材料とする。

## 出力形式

```markdown
### [Sprint Metrics Summary]

| 評価指標                     | 数値          | 評価の根拠                         |
| :--------------------------- | :------------ | :--------------------------------- |
| **Goal Achievement Rate**    | [1-5]         | [具体的な達成内容]                 |
| **Estimation Accuracy**      | [1-5]         | [Tシャツサイズと実労力の乖離分析]  |
| **Quality Integrity**        | [1-5]         | [テスト網羅度とバグ発生状況]       |
| **Collaboration Discipline** | [1-5]         | [セッションメトリクスと規律遵守度] |
| **Velocity**                 | [Σウェイト値] | [乖離要因・文脈のナラティブ]       |
```

> **記録先**: スプリントメトリクスは Retrospective Board に、`harness-metrics-summary`
> （数値JSON）と5指標のナラティブ独立フィールド（`harness-metrics-goal-achievement` /
> `harness-metrics-estimation-accuracy` / `harness-metrics-quality-integrity` /
> `harness-metrics-collaboration-discipline` / `harness-metrics-velocity`）として記録する（カスタム
> フィールドの正の定義は `gateway/field-registry.ts` を参照）。
