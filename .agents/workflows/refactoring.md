# リファクタリング・ワークフロー (/refactoring)

本ワークフローは、既存の振る舞い（Behavior）を一切変えることなく、内部構造（Structure）を洗練させ、保守性や可読性を向上させるための手順を定義します。
**前提条件**: 本ワークフローは、必ず `/session-start`
にてリファクタリング対象の特定と計画の承認が完了した後に呼び出してください。

常に各ステップで呼び出す役割（Role）に定義された制約を厳格に守ってください。

---

## 1. 準備・計測フェーズ

### 1-1. 事前メトリクスの測定

- **ロール**: `@[refactor]` (すべての制約を遵守)
- **セルフチェック**:
  - [ ] 改善前の循環的複雑度や保守性指数を記録し、ユーザーと共有したか。

**停止指示**: 次のステップの内容を先読みして実行してはならない。PO の次の指示を待て。

<!-- STOP -->

### 1-2. テストの健全性確認（中止判断）

- **ロール**: `@[tester]` (すべての制約を遵守)
- **セルフチェック**:
  - [ ] **[必須]** リファクタリング対象をカバーするテストが存在するか。
  - [ ] **[必須]** 現状で全ての関連テストがパス（Green）しているか。
  - [ ] **[中止判断]**
        テストがない、または既に失敗している場合は、**リファクタリングを中止し、オーケストレーター（ユーザー）に「テストの作成または修復」を優先するよう報告したか。**

**停止指示**: 次のステップの内容を先読みして実行してはならない。PO の次の指示を待て。

## 4. 検証・証明フェーズ

        プロジェクト全体の全テストがグリーンであることを確認したか。
  - [ ] リファクタリング対象箇所が、変更後も期待通り動作し続けていることをテストで証明したか。

の次の指示を待機してください。独断で次のアクション（要約等）を提案・実行してはなりません。
