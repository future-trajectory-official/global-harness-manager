# セッション開始ワークフロー (/session-start)

本ワークフローは、セッションの開始にあたってプロジェクトビジョンと保有能力を同期し、最適な専門ロールが戦略を策定する「多角的な合議プロセス」を定義します。

---

## 1. 価値観と能力の同期フェーズ

### 1-1. ビジョンと保有スキルの宣言

- **ロール**: `@[scrum-master]` (進行役として開始)
- **実行スキル**: `@[/verify-vision-capability]`
- **成果物**: 「Vision & Capability Alignment Report」
- **セルフチェック**:
  - [ ] **[価値基準]** `VISION.md` のエッセンスを抽出し、判断基準として宣言したか。
  - [ ] **[能力確認]** 現在のチーム（ロール）と行使可能なスキルを棚卸しし、PO に提示したか。

---

## 2. タスク特定フェーズ

### 2-1. 1セッション1タスクの絞り込み

- **ロール**: `@[scrum-master]` (優先順位の調整)
- **実行スキル**: `@[/identify-session-task]`
- **成果物**: 「Session Task Identification」報告
- **セルフチェック**:
  - [ ] **[1セッション1タスク]** バックログから、迷走を防ぐための最小単位のタスクを特定したか。
  - [ ] **[アサイン]** 次の設計フェーズを担当する**最適な専門家（例：Architect, Consultant, Skill
        Writer 等）**を指名し、**「ここから先は～に委譲します」と明示的に宣言したか。**

---

## 3. 戦略策定（セッション計画）フェーズ

### 3-1. 専門家による詳細設計

- **ロール**: 指名された専門家（例：`@[architect]` / `@[consultant]` / `@[skill-writer]` 等）
- **実行スキル**: `@[/session-planning]`
- **成果物**: `implementation_plan.md` (アーティファクト)
- **セルフチェック**:
  - [ ] **[役割宣言]** 委譲を受けた直後に、自身のロールを改めて宣言したか。
  - [ ] **[Decision-Action Separation]**
        実装ステップを詳細に定義し、AIが独断で書き換えを開始しない「ガードレール」を設けたか。

---

## 4. 合意と承認フェーズ

### 4-1. 計画の承認と WIP 更新

- **ロール**: `@[scrum-master]` (最終確認)
- **セルフチェック**:
  - [ ] **[POの承認]** 実装計画（アーティファクト）に対し、PO からの最終合意を得たか。
  - [ ] **[ステータス管理]** **POの承認を得た後**にはじめて、バックログを `[WIP]` に更新したか。
  - [ ] **[ハンドオフ]**
        実装ワークフロー（例：`/develop-work-package`）へ迷いなく移行できる準備が整ったか。
