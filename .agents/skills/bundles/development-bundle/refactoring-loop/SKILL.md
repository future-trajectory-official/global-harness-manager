# refactoring-loop

このスキルは、Antigravity が「挙動の不変（Behavior
Preservation）」を絶対条件として、コードの技術債を削減し、メトリクスを改善するための手順を定義します。

## 前提条件

- 対象コードに対して 100% のカバレッジ（または主要な挙動を網羅する）テストが存在し、全て GREEN
  であること。

## 実行手順

1. **環境判定とメトリクス計測ガイドのロード**
   - 言語に応じた計測・分析方法を確認してください。
     - Deno/TypeScript: [deno-ts.md](./references/deno-ts.md)
     - Python: [python.md](./references/python.md)

2. **ターゲットの選定 (Pre-analyze)**
   - 静的解析結果や「コードの臭い（重複、長すぎる関数等）」に基づき、修正対象を1箇所に絞り込んでください。

3. **最小単位の修正 (The Smallest Change)**
   - 関数の抽出、命名変更、ロジックの簡素化など、**外部インターフェースを変えない**修正を行ってください。
   - 修正のたびにテストを実行し、1秒でも長く RED の状態を維持しないようにしてください。

4. **検証と事後計測 (Post-verify)**
   - 再度テストを実行し、全て GREEN であることを確認してください。
   - メトリクス（行数削減、複雑度低下、警告解消など）が改善されたことを確認し、ユーザーに報告してください。

5. **結果の報告**
   - **成功**: テストが GREEN
     かつメトリクスが改善された状態であることを確認し、上位ワークフローに報告してください。
   - **失敗**:
     テストが落ちた（RED）場合、またはメトリクスが改悪された場合は、直ちにその旨を上位ワークフローに報告してください。プロダクトコードに合わせてテストコードを修正することは、このスキル内では原則禁止です。

## 注意事項

- **ビッグバン・リファクタリングの禁止**: 一度に大量のファイルを書き換えてはいけません。
- **機能追加の禁止**: リファクタリング中にバグ修正や機能追加を混ぜないでください。
- **証拠の提示**:
  改善前後のメトリクス比較（例：複雑度が10から5に下がった等）を可能な限り数値で示してください。
- **Git操作について**: このスキル内ではステージング、コミット、リストア等の Git
  操作は行いません。結果の報告を受けた上位ワークフローの指示に従ってください。
