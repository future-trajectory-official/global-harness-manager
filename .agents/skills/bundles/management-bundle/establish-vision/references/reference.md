# ビジョン要素の深掘り質問集

## 対象ユーザー

- 一番最初にこのプロダクトを使って熱狂してくれる人は、どんな人か？
- その人は今どんな課題を抱えているのか？
- ユーザーを「全員」とするとメッセージが拡散する。優先順位はどうか？

## 提供価値

- ユーザーはこのプロダクトで「何ができるようになる」のか？
- 「So That」連鎖: それができると、その結果どうなる？ → さらにその先は？
- 競合や代替手段（Excelや手作業等）と比べて何が決定的に違うのか？

## 差別化要因

- 既存の代替手段をユーザーが使わない理由は何か？
- このプロダクトにしかできない唯一無二の要素は何か？

## アウトカム

- このプロダクトが普及した世界で、ユーザーの1日の流れはどう変わるか？
- 3年後、このプロダクトが当たり前になった世界を想像してください — どんな変化が起きていますか？

# 入力 JSON の組み立て

収集した情報を以下の形式にマッピングする。scope（owner/repository）と title
はスクリプトが自動解決するため入力不要。

```json
{
  "targetAudience": "<対象ユーザー>",
  "value": "<提供価値>",
  "differentiator": "<差別化要因>",
  "outcomes": [
    { "title": "<アウトカム名>", "description": "<説明>" }
  ]
}
```

# 実行

```bash
# dry-run（事前確認） — ユーザーに内容を提示し承認を得る
echo '<JSON>' | deno run -A .agents/skills/bundles/management-bundle/establish-vision/scripts/establish_vision.ts --dry-run

# 本実行（ユーザー承認後）
echo '<JSON>' | deno run -A .agents/skills/bundles/management-bundle/establish-vision/scripts/establish_vision.ts
```

# [VISION.md](/.agents/management/VISION.md) テンプレート（参考）

プロダクトビジョンを独自に管理する場合のローカルファイルテンプレート。各項目の記述例も併せて参考にすること。

```markdown
# プロダクトビジョン

## ビジョンステートメント

**エレベーターピッチ (So That)**: <対象ユーザー> が <機能> を使うことで、<最終的なアウトカム>
になれるようにする。

**動機・情熱の源泉 (Passion)**:
なぜこのプロジェクトをやりたいのか。ビジネス的価値だけでなく、開発者自身の純粋な欲求。

**対象ユーザー**: 誰のためのプロダクトか。初期に熱狂してくれる具体的なペルソナを含めて記述。

**提供する価値**: ユーザーが得られる体験を、具体的な動詞で記述。

**差別化要因**: 競合や既存の代替手段では満たせない要素。

---

## ターゲット・アウトカム

このプロダクトが普及したとき、ユーザーの日常はどう変わるかを「〜できる」形式で記述。

- <変化 1>
- <変化 2>
- <変化 3>
```

### 記述例

```
**エレベーターピッチ (So That)**:
誰もが「即座に規律あるAI協働開発を始められる」ようにすることで、AIとの対話を通じた「設計者としての成長（共進化）」を実現する。

**対象ユーザー**:
AIを活用したソフトウェア開発の初心者、およびAIとの協働を通じて設計者・管理者としての視座を獲得したい中級開発者。

**提供する価値**:
本リポジトリをクローンし、オンボーディングを実行するだけで、役割定義・ワークフロー・品質基準が自動的にプロジェクトへ組み込まれる。

**差別化要因（AI-Human Co-evolution）**:
意思決定の背景やトレードオフをAIに「教育的に説明させる」ことで、ユーザー自身が判断スキルを自然に身につけることができる点。

**ターゲット・アウトカム**:
- 即座に始められる: クローンとオンボーディングだけで環境が整う。
- 迷わず進められる: ワークフローに沿うだけで品質が担保される。
- 使うほど成長できる: AIとの対話を通じて設計・管理の視座が磨かれる。
- どこでも通用する: 培った規律は技術スタックを問わず移植できる。
```
