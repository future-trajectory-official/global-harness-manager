# Sprint Planning 🎯

ユーザー（プロダクトオーナー）と共に、このスプリントで開発する機能についてすり合わせを行い、直ちに実装へ移れるように詳細なタスクへと落とし込むスキルです。このセッションでは**コードの実装は一切行いません**。

## 🎯 スキルの目的

- スプリント対象のプロダクトバックログアイテム（PBI）を、具体的かつ実行可能なタスクへ分解する。
- 開発者が迷いなく着手でき、人間（ユーザー）とAIの協働作業がスムーズに流れるような「道筋（ロードマップ）」を構築する。

## 🔄 実施フロー

### 1. 現状確認とガイドラインの参照

- **プロダクトバックログ** ([product-backlog.md](/.agents/management/product-backlog.md))
  を読み込み、スプリントバックログのバックログアイテム（PBI）をピックアップします。
- **運用ガイドライン** ([backlog-guidelines.md](/guides/backlog-guidelines.md))
  を読み込み、見積り基準やステータス管理の作法を確認します。

### 2. タスクの細分化

- 着手対象となる機能について、具体的な技術タスクに分解します。
- **【人間中心設計】** 開発タスクだけでなく、ユーザー（人間）側での操作が必要となる
  **手続き的タスク（外部サービスのアカウント登録、環境設定など）** も洗い出します。
- **【ユーザー支援】**
  ユーザーの操作タスクに対し、「英語フォーム用の記入テンプレートの作成」や「入力補助用のナビゲーションガイド」など、ユーザーの心理的・技術的ハードルを下げるための
  **操作支援用タスク** も併せて設計し、リストに組み込みます。
- 各タスクに対し、**T シャツサイズ**による見積りを適用します。
- **技術的不確実性の検出**: PBIの見積り時に技術的不確実性が認められる場合、
  [spike-issuance-at-sprint-planning.md](/.agents/skills/bundles/management-bundle/sprint-planning-old/references/spike-issuance-at-sprint-planning.md)
  に従い、PO判断でスパイクWP（`WP_0`）の発行を検討します。

### 3. ステータス付与とドキュメント更新

- 各 PBI とタスクに対し、初期ステータス `[TODO]` を付与します。
- **ステータスの運用ルール**:
  - 未着手: `- [ ]` (PBI ステータス: `[TODO]`)
  - 作業中: `- [x]` (PBI ステータス: `[WIP]`) ※タスクが 1 つでも完了したら PBI は `[WIP]`
  - 完了済: `- [x]` (PBI ステータス: `[DONE]`) ※全てのタスクが完了したら PBI は `[DONE]`

### 4. ユーザーへの報告と承認

- 整理したタスクツリーと今後の進め方を報告し、承認を得ます。
- **報告の出力仕様**: プランニング結果の報告には、以下の2点を必ず含める必要があります。
  1. **合計スプリントウェイトの算出と上限比較**:
     今スプリントに計画された全PBIの合計ウェイトを算出し、プロダクトバックログに定義された「推奨スプリントウェイト上限
     (Recommended Sprint Weight
     Cap)」と比較した結果。上限を超過している場合は、超過した理由およびPOとのリスク合意内容を明示すること。
  2. **セマンティック分割のチェック結果**:
     スプリント対象の各PBIが、ユースケースやユーザーストーリーレベルでの関心の境界で適切に細分化されているか（無関係な変更が混在していないか）のチェック結果。
- 更新が完了したら、期待される結果を満たしたことを示すため、更新エビデンス（タスク一覧や見積り結果など）を提示して完了を宣言します。

## ⚠️ 注意事項

- 本スキルを実行中は、**いかなるプログラムの実装や PR 作成、環境操作も行わないこと**（"No
  Development" ルール）。
- あくまで「指名された自身の専門役割」として、ユーザーの合意支援とタスクの細分化ファシリテーションに徹すること。
