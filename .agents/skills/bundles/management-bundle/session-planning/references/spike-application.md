# スパイクWPのセッション計画への適用方法

本ドキュメントは、`session-planning` スキルがスパイクWP（Spike Work
Package）およびスパイク後の本実装WPを扱うための具体的な手順を定義する。スパイクWPの概念定義は
[backlog-guidelines.md 2.2.3](/.agents/management/backlog-guidelines.md#223-スパイクwp-spike-work-package)
を参照すること。

本ドキュメントが扱うのは以下の2つのケースである。スパイクWP自体の発行判断（スプリントプランニング時のPO判断）は本ドキュメントの対象外とする。

## ケースA: スパイクWP（`WP_0`）のセッション計画

`WP_0`
は技術的不確実性を解消するための事前調査WPである。通常のWPとは異なり、実装ではなく**調査・検証**を目的とする。

- ACには調査範囲・検証項目・合格基準を明記し、際限のない調査を防ぐ。
- 調査の完了条件（合格基準）を明確に定義すること。
- 調査レポートは後続の本実装WP（`WP_M'`）のバックログに `- **参照**: [link-to-report]`
  形式で明記する。
- スパイクWPの完了をもって本実装WP（`WP_M'`）の `session-planning` を開始可能とする。

## ケースB: スパイク後本実装WP（`WP_M'`）のセッション計画

`WP_M'` は `WP_0`（スパイクWP）の調査結果を反映した本実装WPである。以下の手順で計画を策定すること：

1. `WP_M'` のバックログに `- **参照**: [link-to-spike-report]`
   形式の参照リンクが存在することを確認する。
2. 該当リンク先の資料（`WP_0` の調査レポート）を**必ず読込み**、調査結果を計画に反映する。
3. 調査レポートで確定した技術選定・アーキテクチャ判断を計画の前提条件として明記する。

この参照リンクはスパイクWPの成果物であり、本実装WPの前提条件である。参照リンクが存在しない場合は、本実装WPの計画策定に必要な情報が不足している可能性があるため、POに確認すること。
