# plan-sprint-review リファレンス

## スプリントレビュー検証計画とは

スプリントレビューは、POが**スプリントゴールに対する各PBIのAC達成状況を確認・承認する**場である。
本スキルはその準備として、「何を（PBI/WP/AC）」「どのように（検証方法）」「どうなったら合格か（判定基準）」を
❔ **未確認**の状態で列挙した**検証台帳**を作成する。

この検証台帳をもとに、後続の `execute-sprint-review`
スキルが実際の検証を実行し、各ACの合否を記録する。

### このスキルがやること

- スプリント内の全PBI/WP/ACを ❔ 未確認で列挙する
- 各ACに検証方法（どのワークフローを実行し、何を確認するか）を紐付ける
- 検証台帳を永続化し、レビュー実施時の判断基準とする

### このスキルがやらないこと

- 各ACの合否判定の実行と記録（`execute-sprint-review`）
- レビューの完了処理（`archive-sprint-review`）

## 検証方法の引き出し方

各ACに対して、POから具体的な検証方法を引き出すための質問パターン。

### 基本の問いかけ

ACごとに、以下の3点をPOに問いかける：

1. **「このACは、何を確認すれば合格と言えますか？」**
   - 合格の定義を明確にする
   - 例：「Review Issue が作成され、そのURLが出力されること」
2. **「その確認は、どのように行いますか？」**
   - 検証手段を特定する
   - 例：「sprint-start ワークフローを実行して確認する」
3. **「その確認は、誰が（何が）実行しますか？」**
   - 自動化の有無を判断する
   - 例：「ワークフローが自動実行する」/ 「POが目視確認する」/ 「AIがドキュメントを確認する」

### 検証手段の分類と質問例

| 検証手段           | 質問例                                                                             | 記述例                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| ワークフロー実行   | 「このACは、sprint-startの中で検証できますか？それとも独立したスキル実行ですか？」 | 「sprint-start の Phase 2 実行後、Review Issue が作成され、本文に全ACが ❔ で記録されていることを確認する」 |
| CLI / コマンド実行 | 「このACは、特定のコマンドを実行して結果を確認しますか？」                         | 「plan-sprint-review --dry-run を実行し、Plan 構造が JSON で出力されることを確認する」                      |
| 目視確認 / UI操作  | 「このACは、画面やファイルを直接見て確認しますか？」                               | 「PR #427 の diff を確認し、Review ハンドラが登録されていることを確認する」                                 |
| AIによる検証       | 「このACは、AIにドキュメントやコードを確認させますか？」                           | 「SKILL.md を確認し、Quick-Start 行数 < 詳細手順行数 かつ リファレンスへのリンクが存在することを確認する」  |
| テストスイート     | 「このACは、テストを実行して確認しますか？」                                       | 「deno task qa を実行し、plan_sprint_review_test.ts を含む全テストがパスすることを確認する」                |
| POによる判断       | 「このACは、POが最終的に判断しますか？」                                           | 「スキルの出力をPOが確認し、期待通りであることを承認する」                                                  |

### 悪い例と良い例

| 悪い例（曖昧で非具体的）       | 良い例（具体的で検証可能）                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 「テストが通ることを確認する」 | 「deno task qa を実行し、review-usecase_test.ts の plan 関連テスト4件が全てパスすることを確認する」                      |
| 「コードレビューする」         | 「PR #428 の diff を確認し、ReviewUseCase.plan() に planInput パラメータが追加されていることを確認する」                 |
| 「スキルが動くことを確認する」 | 「plan-sprint-review --dry-run を実行し、Plan の summary に "Plan review: Sprint 17 Review" と出力されることを確認する」 |

### 検証計画の完成チェックリスト

POとの対話が終わったら、以下を確認する：

- [ ] 全ACに検証方法が設定されているか
- [ ] 各検証方法が「何を」「どうやって」確認するか具体的に書かれているか
- [ ] 「deno task qa を実行する」「コードレビューする」といった曖昧な表現になっていないか
- [ ] 手段（ワークフロー/CLI/目視/AI/テスト）がACの性質に適しているか

## 入力 JSON の形式

```json
{
  "sprintNumber": 17,
  "pbis": [
    {
      "number": 1,
      "title": "[Sprint17/ReviewSkills]/Create-sprint-review-skill-set",
      "wps": [
        {
          "number": 1,
          "title": "Gatewayアダプター拡張",
          "acs": [
            {
              "number": "1",
              "description": "ReviewUseCase.planを呼び出しReview Issueを作成するPlanを生成する",
              "verificationPlan": "sprint-startのPhase 2実行後、Review Issueが作成され、タイトル・スプリント・全ACが ❔ で記録されていることを確認する"
            },
            {
              "number": "2",
              "description": "dry-runモードがPlanをJSONで出力しgh CLI操作を行わない",
              "verificationPlan": "--dry-run 実行時の出力にPlan構造が含まれ、実際のIssue作成が行われないことを確認する"
            }
          ]
        }
      ]
    }
  ]
}
```

### 各フィールドの説明

| フィールム               | 必須 | 説明                                                                                         |
| ------------------------ | ---- | -------------------------------------------------------------------------------------------- |
| `sprintNumber`           | 必須 | レビュー対象のスプリント番号                                                                 |
| `pbis`                   | 必須 | レビュー対象のPBI一覧                                                                        |
| `pbis[].number`          | 必須 | PBI番号（バックログ上の識別子）                                                              |
| `pbis[].title`           | 必須 | PBIタイトル                                                                                  |
| `pbis[].wps`             | 必須 | 当該PBIに属するWP一覧                                                                        |
| `wps[].number`           | 必須 | WP番号                                                                                       |
| `wps[].title`            | 必須 | WPタイトル                                                                                   |
| `wps[].acs`              | 必須 | 当該WPに属するAC一覧                                                                         |
| `acs[].number`           | 必須 | AC番号                                                                                       |
| `acs[].description`      | 必須 | ACの内容                                                                                     |
| `acs[].verificationPlan` | 任意 | 具体的な検証手段（ワークフロー実行 / CLI操作 / 目視確認 / AI検証等）と、確認すべき項目を記述 |

## 実行例

```bash
# Sprint 17 の検証計画を立案（dry-run）
echo '{"sprintNumber": 17, "pbis": [{"number": 1, "title": "PBI例", "wps": [{"number": 1, "title": "WP例", "acs": [{"number": "1", "description": "AC例", "verificationPlan": "dry-runで確認"}]}]}]}' | deno run -A .agents/skills/bundles/management-bundle/plan-sprint-review/scripts/plan_sprint_review.ts --dry-run
```

## 生成される検証台帳の内容

作成されるIssueには以下の情報が記録される：

- **スプリント番号**: 対象スプリント
- **凡例**: 各ACの判定結果の見方（❔未確認 / ✅合格 / ⚠️条件付き / ❌不合格 / ➖論理削除）
- **PBI/WP/ACの一覧**: 全ACが ❔ 未確認で列挙される
- **検証方法**: 各ACに紐付く具体的な検証手段と確認項目

```
## Sprint Review

- **Sprint**: Sprint 17

## 凡例

- ❔ 未確認（初期状態）
- ✅ 合格
- ⚠️ 条件付き合格
- ❌ 不合格
- ➖ 論理削除

## 計画時確認項目

### 📦 PBI: [1] PBIタイトル

#### WP_1: WPタイトル

- ❔ AC_1: ACの説明
  - **検証方法**: 検証手順の説明
- ❔ AC_2: ACの説明
```

## エラーハンドリング

- `sprintNumber` が指定されていない、または不正 → エラーで処理中断
- `pbIs` が空または不正 → エラーで処理中断
- システム的な接続障害 → エラーが報告され処理中断
