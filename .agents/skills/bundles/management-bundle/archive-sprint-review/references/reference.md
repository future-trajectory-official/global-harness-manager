# archive-sprint-review リファレンス

## 総合判定と対話パターン

総合判定の意味や判定基準の詳細は `guides/design-spec.md`（Review の設計仕様）を参照すること。

### 総合判定別のAI応答

| 総合判定        | AI → PO のメッセージ                                                                                                              | PO → AI の応答                            | 次のアクション |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | -------------- |
| **pass**        | 「総合判定は合格です。スプリントレビューをアーカイブしますか？」                                                                  | 「はい」                                  | archive へ     |
|                 |                                                                                                                                   | 「まだ」                                  | 終了           |
| **conditional** | 「条件付き合格です（次スプリントに先送りする項目があります）。次スプリント向けの追跡PBIを作成し、その後アーカイブしてください。」 | 「追跡PBIは作成済みなのでアーカイブして」 | archive へ     |
|                 |                                                                                                                                   | 「まだ作成していないので保留」            | 終了           |
| **fail**        | 「総合判定は不合格です。修正PBI/WPを作成し完了後、再度 execute-sprint-review を実施してください。」                               | 「それでもアーカイブする」                | archive へ     |
|                 |                                                                                                                                   | 「わかった、中断する」                    | 終了           |
| **未設定**      | 「スプリントレビューが未実施です。先に execute-sprint-review を実行してください。」                                               | 「それでもアーカイブする」                | archive へ     |
|                 |                                                                                                                                   | 「わかった」                              | 終了           |

### 処理判断の原則

- 総合判定と個別AC判定は独立している。本スキルは総合判定のみを判断材料とする
- pass/conditional はクローズを推奨、fail/未設定 はクローズ非推奨とする
- 推奨に反するクローズはPOの強制判断として許可する

## examine と archive の役割

| サブコマンド | 目的                     | 副作用               |
| ------------ | ------------------------ | -------------------- |
| **examine**  | 状態確認とPOへの情報提示 | なし（読み取りのみ） |
| **archive**  | アーカイブ               | あり（書き込みあり） |

examine → archive の2段階により「状態確認→PO判断→実行承認」のガードレールを実現する。

## dry-run 出力の解釈

dry-run の出力は Plan（操作手順）をJSONで返す。AIはこれを人間向けに翻訳してPOに説明すること。

例：「スプリントレビューをアーカイブします。実施報告を閉じ、アーカイブ済みであることを記録します」

## エラーハンドリング

- 現在スプリントの実施報告不在: 該当なしとして終了
- overallResult 未設定: archive 実行時にバリデーションエラー（examine 時点で AI が注意喚起済み）
