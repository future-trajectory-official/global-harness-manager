# KPT生成ガイド

介入履歴をインプットに、セッション単位のKPTを生成するためのガイドライン。

## KPTの定義

| 項目        | 問い                                           | 起点とするデータ                         |
| ----------- | ---------------------------------------------- | ---------------------------------------- |
| **Keep**    | 今回、AI×POの協働で良かった点は何か            | 介入なしのフェーズ、スムーズに進んだ局面 |
| **Problem** | 介入から見えるプロセスまたは関係性の課題は何か | 介入種別とその事実                       |
| **Try**     | 次回、何を変えればProblemが改善するか          | Problemに対応する改善アクション          |
| **Advise**  | AIからPOへの率直な提案                         | 協働パターン全体からAIが気づいたこと     |

## 介入がない場合

介入が1件もなかったセッションでは、Problem/Tryは「現状維持で問題なし」としてもよい。
ただしKeep/Adviseは必ず記録し、良かった点とさらなる改善余地を言語化する。

## 生成例

**介入「計画深度不足（1回）」の場合**:

- Keep: 着手後の修正が少なく、計画の骨子は適切だった
- Problem: AIが計画時にPOの想定スコープを過小推定した
- Try: 着手前にAIが全ACの詳細度をPOと1件ずつ確認する
- Advise: POから「このケースも考慮して」のフィードバックが早期に得られ、手戻りが最小限で済んだ

**介入なしの場合**:

- Keep: 計画から実装まで一貫した進行で、POの介入が不要だった
- Problem: 特になし（現状の進め方を継続）
- Try: 次回も同様の進め方を維持する
- Advise: POの要件定義が明確だったため、AIの推論とズレが生じなかった
