# Session Metrics Guide

セッションごとの協働品質を測定するための指標定義です。

## 指標の定義

### 1. Intent Alignment Rate (意図の整合率)

- **定義**: 1タスクあたりの「意図の修正（やり直し指示）」回数。
- **採点基準**:
  - 1: ほぼ全てのステップでやり直しが発生した。
  - 3: 中核的な意図は伝わったが、細部の修正が数回必要だった。
  - 5: 最初の指示のみで、一度も意図のズレによる修正がなく完遂した。

### 2. Constraint Adherence Score (制約遵守スコア)

- **定義**: セッション中の制約違反（例：独断操作、ルール無視）の回数。
- **採点基準**:
  - 1: 重大な制約違反（[CRITICAL ACTION] の無視等）が発生した。
  - 3: 軽微なルール違反（命名規則の誤り等）が1-2回あった。
  - 5: 全ての制約・ルールを完璧に遵守した。

### 3. Context Extraction Quality (コンテキスト説明の質)

- **定義**:
  AIが「なぜその設計にしたか」「どのようなトレードオフを考慮したか」を論理的に説明できた度合い（AIによる自己評価）。
- **採点基準**:
  - 1: 理由の説明がなく、結果だけを提示した。
  - 3: 表面的な理由は説明したが、深い設計思想までは言及しなかった。
  - 5: ユーザーが納得する深い洞察とトレードオフの説明が含まれていた。

### 4. Work Size Stability (作業単位の安定性)

- **定義**: タスク分割の細かさが適切かつ安定しているか。
- **採点基準**:
  - 1: 作業単位が巨大すぎてリスクが高かった、あるいは細かすぎて効率が悪すぎた。
  - 5: 常に管理可能な「1セッション1タスク」の粒度が保たれていた。

## 2. 拡張データスキーマ（Effort測定およびID管理）

セッションメトリクスファイルには、協働品質指標に加えて、以下の管理メタデータおよび
Effort（介入回数）が記録されます。

### 1. ID管理フィールド

階層構造がない場合にも柔軟に対応するため、個別に独立して保存します。

- **`epic_id`**: 関連するエピックの識別キー（例: `RobustSkillArchitecture` 等）。
- **`feature_id`**: 関連するフィーチャーの識別キー（例: `SkillGovernance` 等）。
- **`pbi_id`**: 関連するプロダクトバックログアイテムの識別キー（例: `Sprint-Scope-Skill-References`
  等）。

### 2. Effortの3点見積もり（数値入力）

セッションごとに、具体的なPO（人間）の介入回数の数値（`0, 1, 2, 3...`）を記録します。

- **`initial_estimated_effort`**: タスク選択時に最初に見積もった想定介入回数。
- **`planned_estimated_effort`**: 計画が完了し、POから合意を得た時点での最終予測介入回数。
- **`actual_effort`**: 実装完了後、実際に発生したPOの介入回数の実績。

### 3. テキスト記録の区別

- **`metrics_reason` (旧 `reason`)**: 協働品質の4つの採点指標（Intent, Constraint, Context,
  Stability）の点数を決定した背景・思考プロセスを記録します。
- **`effort_variance_reason`**:
  3点見積もりの数値に乖離が発生した具体的な理由、または予実が一致して極めてスムーズに完了した要因を記録します。

#### 💡 スムーズだった（予実一致）場合の要因記述例：

予実が一致、あるいは実績 `0`
回で非常に円滑に進行した場合も、何が成功要因だったかを必ず言語化します。

> _記述例:_
>
> - 「PBIに記載されていたAC（受け入れ基準）が極めて明瞭で、実装上の迷いが生じなかったため。」
> - 「計画策定時に設計レベルでPOとすり合わせが完璧に完了しており、実装フェーズでの手戻りが一切発生しなかったため。」
> - 「変更対象のモジュールが疎結合に設計されており、副作用の調査が瞬時に完了したため。」
