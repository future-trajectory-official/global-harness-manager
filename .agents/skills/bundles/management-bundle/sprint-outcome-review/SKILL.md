# sprint-outcome-review

スプリントの終了時に実行し、スプリントゴールの達成度と生成された成果物のエビデンスを PO
に報告するための専用スキルです。

## 🚀 Quick-Start (実行手順)

本スキルを実行するAI（および人間）は、以下の手順を最短経路で実行してください。

1. **インプット情報の読み込み**
   - [product-backlog.md](/.agents/management/product-backlog.md)
     から対象スプリントのPBIステータスを読み込みます。
   - [review-guide.md](/.agents/skills/bundles/management-bundle/sprint-outcome-review/references/review-guide.md)
     を読み込み、報告テンプレートを把握します。

2. **エビデンスの収集と評価**
   - 完了した各PBIについて、受入基準（AC）を満たしたことを証明する客観的エビデンス（テストパスログ、差分、実機動作ログ等）を整理します。

3. **レビュー要約の出力**
   - ガイドに定義された「Sprint Review
     Report」のフォーマットに沿って要約を出力し、PO（ユーザー）に提示して動作デモの承認を求めます。

4. **レビュー報告書の永続化**: 承認済みレビュー要約を `.agents/management/sprint-review-{N}.md`（N =
   現在のスプリント番号）に保存します。

## 📋 詳細手順

1. **ゴール達成度評価**
   - スプリントゴールとバックログの各PBIの `[DONE]`
     状態を照合し、「完了」および「未完了（持ち越し）」のリストを明確に整理します。

2. **デモ可能インクリメントの検証**
   - 変更されたソースコードおよびテスト実行ログから、実際に「動作するプロダクト（インクリメント）」としての品質が満たされているか、検証エビデンス（全テストグリーンの結果等）を確認します。

3. **レビュー要約の出力**
   - スプリント全体の成果を要約したレビュー報告書を提示し、POにデモの動作確認を求めてください。

4. **レビュー報告書の永続化**
   - PO から承認を得たレビュー要約を `.agents/management/sprint-review-{N}.md`（N =
     現在のスプリント番号）に保存します。
   - 上書き保存とし、常に最新のレビュー報告書を参照可能な状態に保ちます。
   - 保存先は `.gitignore` により git 管理対象外となるため、クリーンな状態が維持されます。
