# assess-context 読み込み・要約・提示規則

本リファレンスは、assess-context が用語集（管理概念とプロジェクト固有の用語）を読み、要約して
提示する際の規則を定める。

## 1. 読み取り対象

| 対象                                 | 扱い   | 説明                                                                  |
| ------------------------------------ | ------ | --------------------------------------------------------------------- |
| `.agents/context/management.md`      | 必須   | ハーネスの管理概念。git追跡対象・配布対象                             |
| `.agents/context/product.md`         | 任意   | プロジェクト固有の用語。git追跡対象外・利用者編集。**未存在でもよい** |
| `.agents/context/product.md.example` | 対象外 | 構造見本。**読まない**（見本用語の混入を防ぐ）                        |

## 2. 要約の単位（出典別）

用語集はファイルごとに役割が分かれている。そのため、当スキルが改めて分類するのではなく、
**出典ごとにまとめて要約・提示する**。

| 出典            | 内容                                                                 | 表示見出し               |
| --------------- | -------------------------------------------------------------------- | ------------------------ |
| `management.md` | ハーネスの管理概念（スコープモデル・状態遷移・指標系・品質要件など） | ■ 管理概念               |
| `product.md`    | プロジェクト固有のセットアップ・配布・標準・ガイドに関する用語       | ■ プロジェクト固有の用語 |

- 概念・用語の具体例を挙げない。**出典ファイルを正の情報源**とし、内容を読解して要約する。

### 出典が重複する場合

- 同一の用語が両ファイルに現れた場合は、`management.md`（ハーネスの管理概念）を正とし、その定義を共有言語として扱う。

## 3. 要約の進め方

1. `management.md` を読み、管理概念を要約する。
2. `product.md` が存在する場合のみ読み込み、固有用語を要約する。存在しない場合は何も読まない。
3. `product.md` が存在しない場合は、プロジェクト固有の用語を「未定義」として扱う。

## 4. 提示範囲と表示規則

- 出典別の見出し（§2 の表示見出し）で種別を分けて提示する。
- `product.md` 未存在時は「■ プロジェクト固有の用語（未定義）」と明示する。
- **提示範囲**: 全量を要約しつつ、現セッションで実際に使う用語を優先的に強調する。
- 各概念・用語は表（または箇条書き）で `用語 / 定義` を一覧表示する。
- 末尾で「この語彙を本セッションの共有言語として用いる」旨を宣言し、PO に確認を促す。
- **永続化**: 要約をセッション記録（例: `.session/notes/`）へ保存し、事後検証できるようにする。
