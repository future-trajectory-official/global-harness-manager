# Optimization Process

## 1. レトロスペクティブからの反省点抽出

- 本環境では `stateless-reset`
  により記憶がリセットされるため、長期的なログ分析ではなく**「直近のセッション終了時に実施されたレトロスペクティブ（反省点）」**を主たる入力源とします。
- 特に以下のパターンを重点的に抽出します。
  - サーバーエラーやツールエラーから復帰した直後のターンで、システムプロンプトに規定された
    **`[RECOVERY LOG]` を用いた Context Sync（文脈同期）** が遵守されていなかったケース。
  - エージェントがスキルの選択に迷った、あるいはユーザーの意図を汲み取れず手動操作に頼ったケース。
  - `SKILL.md` に詳細事項（コード例やJSON定義など）が書かれすぎており、「Sidecar Reference
    Pattern」が守られていないケース。

## 2. 根本原因の特定と解決策の立案

- 抽出した反省点（特に `[RECOVERY LOG]`
  未遵守などのルール違反）がなぜ起きたのか（トリガーキーワードの不足、ワークフローでのリマインド漏れ等）を分析します。

## 3. SKILL や Workflow のアップデート

- 分析結果に基づき、対象スキルの `description` や `tags.trigger`、あるいは `.agents/workflows/`
  内の手順記述を更新します。
- `description`
  は単なる機能説明ではなく「エージェントがどのような文脈でこのルールやスキルを想起すべきか」という視点で書き換えます。

---

## 使用例

「`stateless-reset`
という言葉を知らないユーザーが『履歴を消して最初からやり直したい』と言ったが、エージェントが反応できなかった」というログを見つけた場合：

- `stateless-reset/SKILL.md` の `trigger` に `clear-history` を追加。
- `description` に「履歴を消してやり直したい時」というフレーズを追加。

---

## 注意事項

- 原型の機能を損なうような大幅な書き換えは行わない。
- ユーザーの意図をハルシネーションしないよう、必ずログの事実に基いて改善する。
