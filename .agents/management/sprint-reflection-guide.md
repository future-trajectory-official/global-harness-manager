# スプリント振り返り（予実差分析）ガイドライン

本ガイドラインは、スプリント終了時（`Sprint End`）に、スプリント中の全セッションで測定された実績
Effort（介入回数）を集計し、当初の PBI
見積もり（Tシャツサイズ）の妥当性を評価・すり合わせして、アーカイブに知見を記録するための標準手順を定義します。

---

## 1. 実績 Effort の集計とすり合わせ

スプリント終了の振り返り儀式において、AI と PO は以下の手順で予実すり合わせを行います。

1. **メトリクスログの集計**:
   - `metrics.jsonl` から今スプリント中に完了した全セッションをフィルタリングし、各 PBI に紐付く
     **「実績 Effort（介入回数）の合計」** を算出します。
2. **PBI 見積もりとの整合性チェック**:
   - 以下の「Tシャツサイズ vs
     実績Effort」の相関テーブルに基づき、見積もりが適切であったかを評価します。

| PBI Tシャツサイズ | 想定 Effort (介入回数) | 妥当性の判断基準                                                              |
| :---------------- | :--------------------- | :---------------------------------------------------------------------------- |
| **S**             | 0 〜 1 回              | 実績合計が 0-1 回であれば極めて妥当。2回以上は「AIにとっての見積もり過小」。  |
| **M**             | 2 〜 3 回              | 実績合計が 2-3 回であれば妥当。0-1 回は「見積もり過大」、4回以上は「過小」。  |
| **L**             | 4 〜 5 回              | 実績合計が 4-5 回であれば妥当。3回以下は「見積もり過大」、6回以上は「過小」。 |
| **XL**            | 6 回以上               | 実績合計が 6 回以上であれば妥当。5回以下は「見積もり過大」。                  |

---

## 2. 予実差と乖離要因の分析

POとの対話を通じて、見積もりと実績に乖離が発生した根本原因を分析します。

- **見積もり過大（サイズに対して実績が大幅に少なかった）ケース**:
  - _分析観点_: AIの自律性が非常に高く機能した要因は何か？
  - _典型例_:
    「インターフェースの疎結合化がすでに済んでいたため」「AIが再利用可能な共通モジュールを自発的に活用できたため」
- **見積もり過小（サイズに対して実績が大幅に多かった）ケース**:
  - _分析観点_: 人間の介入が何度も必要になったボトルネックは何か？
  - _典型例_:
    「計画段階でのAC（受入基準）が不透明で、実装中に3回手戻りした（要件定義/プランニングの課題）」「AIが
    Deno 特有のインポート設定で迷走し、POによる手動修正が3回発生した（技術コンテキストの課題）」

---

## 3. PBI アーカイブへの予実記録（インクリメントカード）

分析した知見は、PBI を `product-backlog.md` から削除して `product-backlog-archive.md`
へ移動（アーカイブ）する際に、以下のフォーマットで記述して永続化します。

### アーカイブカード・テンプレート

```markdown
### [DONE] [Epic/Feature]/PBI-Title

- **完了日**: YYYY-MM-DD
- **成果物**: [PR #XX](link) または [ファイル名](link)
- **見積り**: T-Shirt Size (S/M/L/XL)
- **Effort実績 (介入回数)**:
  - 初期見積もり合計: X 回
  - 計画後見積もり合計: Y 回
  - 実績介入回数合計: Z 回
- **予実分析と知見**:
  - _評価_: [妥当 / 見積もり過大 / 見積もり過小]
  - _要因_: なぜ予実が一致したか、あるいは乖離したかの結論（例:
    「ACの記述が完璧で、実装フェーズは介入0で完遂できたため。」）
  - _カテゴリ_: `#Lesson` `#Decision`（適切なタグを付与）
```

これにより、次回以降のプランニングで「類似のPBIをAIがこなす場合の本当のサイズ」を極めて高い精度で予測できるようになり、AI協働における管理レベルが自己進化し続けます。
