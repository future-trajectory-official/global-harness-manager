# Global Harness Manager

このリポジトリは、AIエージェントの役割（Role）・スキル（Skill）・およびワークフロー（Workflow）を「Bundles（束）」として管理し、プロジェクトの規律をシステムレベルで統制する
**グローバルハーネス** です。

## 思想と目的 (Harness Engineering)

本リポジトリは、AIを単なる「作業の丸投げ先」にせず、人間とAIが共に成長する **AI-Human Co-evolution**
を目指しています。

1. **規律のポータビリティ**:
   どのプロジェクトでも、このハーネスを「装着（Attach）」するだけで、定義された高品質な開発プロセスが即座に適用されます。
2. **役割と責任の分離**: `Architect`, `Developer`, `Tester`
   といった明確な役割をAIに与え、各ステップで厳格な制約（DoD等）を課すことで、品質と透明性を確保します。
3. **教育的協働**:
   AIに対して意思決定の背景やトレードオフの説明義務を課すことで、ユーザー自身が「設計・管理者」としての視座を磨くことができます。

## 導入と利用方法 (Getting Started)

ハーネスの利用は、Antigravity（エージェント）との対話を通じて、以下の 3 つのフェーズで行われます。

### 1. 初期構築 (Setup)

まず、環境を整えプロジェクトにハーネスを装着します。

- **オンボーディング**: `> 「/onboard-new-member を実行して」`
  - CLIツールの導入、GitHubアカウントの保護、およびプロジェクトへのハーネスバインドを行います。

### 2. 戦略策定 (Strategic Planning)

次に、何を作るか、どのような順序で進めるかを合議します。

- **バックログ精査**: `> 「/product-backlog-refinement を実行して」`
  - プロダクトオーナー（ユーザー）と対話し、PBI（プロダクトバックログアイテム）を整理・優先順位付けします。
- **スプリント計画**: `> 「/sprint-planning を実行して」`
  - 直近で取り組むべきゴールを定め、PBI を具体的なタスクへ分解します。

### 3. 実行サイクル (Development Loop)

日々の作業は、以下のサイクルを繰り返して品質を担保します。

1. **セッション開始**: `> 「/session-start を実行して」`
   - 今回取り組むタスクを特定し、専門ロールが詳細な実装計画を策定します。
2. **タスク開発**: `> 「/develop-work-package を実行して」` (または `/refactoring`)
   - TDD（テスト駆動開発）に基づき、安全にコードの実装・改善を行います。
3. **セッション終了**: `> 「/session-end を実行して」`
   - 成果を要約し、KPT形式で振り返りを行い、次回のコンテキストを繋ぎます。

## ディレクトリ構成

- `.agents/`: ハーネスの中核となるエージェント資源。
  - `skills/bundles/`: 機能ごとにカプセル化されたスキル群。
    - `onboarding-bundle`: 環境構築や検証に関わるスキル。
    - `management-bundle`: 計画策定やバックログ管理に関わるスキル。
    - `development-bundle`: TDD実装やサンドボックス構築に関わるスキル。
    - `meta-bundle`: エージェント自身の最適化や文脈同期に関わるスキル。
  - `rules/`: 各ロール（専門家）の行動指針と制約。
  - `workflows/`: タスク完遂までの標準化された手順書。
  - `management/`:
    プロジェクトの頭脳。ビジョン、バックログ、および実施中の実装計画書（Implementation
    Plan）を管理。
  - `core/`: ハーネス全体で共有される共通ユーティリティ。
- `config/`: 環境固有の設定。`.example` ファイルを元に作成します。

## メンテナンスと拡張

本ハーネス自体の検証には、`.agents/skills/bundles/onboarding-bundle/check-harness-configs/`
配下の検証スクリプトを使用します。構造を変更した際は、必ずこの検証ツールも更新し、規律の健全性を保ってください。
