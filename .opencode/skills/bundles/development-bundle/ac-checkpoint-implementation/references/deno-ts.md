# Deno/TypeScript TDD リファレンス

Deno 環境で TDD を実行する際の具体的なコマンドとベストプラクティスです。

## 推奨コマンド

### 1. テスト実行 (RED/GREEN確認)

```bash
deno test -A --parallel
```

- `-A`: 必要な権限を許可（必要に応じて絞り込む）。
- `--parallel`: 高速化（副作用がない場合）。

### 2. 品質検証 (DoDの一括実行)

```bash
# 全ての検証（フォーマット、リント、タイプチェック、テスト）をまとめて実行
deno task qa
```

#### 個別の検証コマンド

```bash
# フォーマットの整合性 (修正せずにチェックのみ)
deno fmt --check

# リンター (公式ルール)
deno lint

# 構文および型の整合性チェック
deno check **/*.ts
```

### 3. カバレッジの測定

```bash
# カバレッジデータの収集 (設定済みの cov_profile を指定)
deno test -A --coverage=cov_profile

# カバレッジ詳細の表示 (または lcov 形式の出力)
deno coverage cov_profile
```

- **⚠️ 必須要件**: カバレッジディレクトリには、`.gitignore` であらかじめ除外設定されている
  `/cov_profile/` （ドットなし）を必ず使用してください。任意のディレクトリ（`.coverage`
  など）を指定して実行してはなりません。

## テストドキュメント規約

各テストケース（`Deno.test()`）の直前に、JSDoc を用いて以下の内容を日本語で記述すること。

```typescript
/**
 * ユースケース: ユーザー一覧取得APIが正常にレスポンスを返すこと
 * 検証意図: ステータスコード200が返り、ユーザー配列が空でないことを確認する
 */
Deno.test("GET /api/users returns user list", async () => {
  // ...
});
```

## 実装のポイント

- **テストコードの配置**: 原則として実装ファイルと同じディレクトリに `filename_test.ts`
  として配置します。
- **標準ライブラリの活用**: `@std/assert` を使用してください。
- **モック**: 外部通信やファイル操作が伴う場合は、`Deno.Command`
  のモックや一時ディレクトリを活用してください。
