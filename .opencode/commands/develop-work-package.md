# /develop-work-package — 汎用Work Package開発ワークフロー

本コマンドはワークフロー `develop-work-package` をメインセッションで実行するための入口です。
**手順の単一の正は以下のワークフロー定義ファイルです。全文を読み、記載どおりにフェーズ進行すること。**

@.agents/workflows/develop-work-package.md

## 実行順序と状態遷移（呼出側の概要）

| フェーズ | 実行スキル | 実行後の状態（業務用語） |
| --- | --- | --- |
| 1-1. 開発環境のセットアップ | develop-environment-setup | 計画で決めたツールチェーン・実行環境が構成され起動可能 |
| 2-1. 作業ブランチの作成 | initialize-branch | 目的承認の上、作業ブランチが作成済み |
| 2-2. インフラ・基盤実装とWIP保存 | hybrid-triage-commit | 基盤実装完了、WIPセーブポイント作成済み |
| 2-3. TDDによる機能実装とWIP保存 | tdd-implementation / hybrid-triage-commit | TDDサイクル完了・指標提示、WIPセーブポイント作成済み |
| 3-1. 網羅的な品質検証 | —（直操作） | プロジェクト全体qaがGreen、カバレッジが実装前以上 |
| 3-2. 軽度のリファクタリング（仕上げ） | —（直操作） | コード洗練完了、全テストGreen再確認済み |
| 4-1. コミット履歴のトリアージと再構築 | hybrid-triage-commit | WIP履歴がアトミックコミットへ再構築・検証済み |
| 4-2. PR作成と報告 | create-pull-request | 変更要約とセッション外変更込みのPRが作成済み |
| 4-3. マージとクリーンアップ | merge-branch | 明示承認後PRマージされ環境が同期済み |

## 遵守事項

- ワークフロー内の `<!-- STOP -->` と停止指示は Opencode の機能ではなく AI への指示表記である。到達点で必ず報告し、PO の明示的な指示があるまで次のフェーズを先読みしない。
- コマンドは呼出側の事情（実行順序・状態遷移）のみを表現する。各実行スキルの内部操作（手順・コマンド・JSON形式）には踏み込まない。
- 並行実行を要する個所がある場合、コマンド自身はサブエージェントを起動せず、該当スキル側がサブエージェントの作成・実行を明示的に行う方針に従う（本ワークフローに並行実行個所なし；将来のスキル変更時もこの方針を維持する）。
