# /sprint-start — Sprint Start Workflow

本コマンドはワークフロー `sprint-start` をメインセッションで実行するための入口です。
**手順の単一の正は以下のワークフロー定義ファイルです。全文を読み、記載どおりにフェーズ進行すること。**

@.agents/workflows/sprint-start.md

## 実行順序と状態遷移（呼出側の概要）

| フェーズ | 実行スキル | 実行後の状態（業務用語） |
| --- | --- | --- |
| Phase 1-0. 用語の同期 | assess-context | 用語集要約を提示し、共有言語をPO確認済み |
| Phase 1-1. プロダクトゴールの確認 | assess-goal-continuation | Product GoalをPOへ提示し、継続またはピボット確定 |
| Phase 2. プロダクトバックログリファインメント | product-backlog-refinement | バックログが最新化され、候補PBIのサイズ見積り済み |
| Phase 3. 分類階層の改善とPBI配置 | refine-classification-hierarchy | エピック/フィーチャー階層が最新化され、PBI配置済み |
| Phase 4. スプリント開始宣言 | begin-sprint | スプリントが作成され、スプリントゴール設定済み |
| Phase 5. スプリントプランニング | sprint-planning | 選定PBIでスプリントバックログが確定 |
| Phase 6. 作業分解 | define-work-package | WPがAC・初期見積り付きで作成されスプリントに確定 |
| Phase 7. スプリントレビュー計画 | plan-sprint-review | レビュー検証計画が確定しReviewエンティティ永続化済み |
| Phase 8. 振り返りの計画 | plan-retrospective | 対象スプリントの振り返りが新規作成され記録準備完了 |

## 遵守事項

- ワークフロー内の `<!-- STOP -->` と停止指示は Opencode の機能ではなく AI への指示表記である。到達点で必ず報告し、PO の明示的な指示があるまで次のフェーズを先読みしない。
- コマンドは呼出側の事情（実行順序・状態遷移）のみを表現する。各実行スキルの内部操作（手順・コマンド・JSON形式）には踏み込まない。
- 並行実行を要する個所がある場合、コマンド自身はサブエージェントを起動せず、該当スキル側がサブエージェントの作成・実行を明示的に行う方針に従う（本ワークフローに並行実行個所なし；将来のスキル変更時もこの方針を維持する）。
